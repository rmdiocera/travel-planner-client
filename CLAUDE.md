# CLAUDE.md

Guidance for working in this repo. Update it when conventions change.

## What this is

**Dayfarer** — the Nuxt 4 / Vue 3 frontend for a travel planner. It talks to a separate **Laravel API** (`/api/v1/...`, Laravel Sanctum auth) that is not in this repo. Users manage **itineraries** (shown as "trips", grouped as ongoing / upcoming / unscheduled / past; a trip may have no dates yet); **places** (with tags and images) are managed from an admin page. A Guest at `/` sees the **Welcome page**: an animated hero, "How it works" and a closing band, all leading to registration.

Stack: Nuxt 4 (`srcDir: 'app/'`), Nuxt UI 4 (Tailwind 4), `@nuxt/image`, `@nuxt/fonts`, `nuxt-auth-sanctum`, VueUse (with `@vueuse/integrations` and `sortablejs` for dragging), `@internationalized/date`, ESLint (`@nuxt/eslint`, stylistic on), Vitest.

## Commands

```bash
npm run dev          # http://localhost:3000
npm run build | generate | preview
npm run lint         # eslint .   (lint:fix to autofix)
npm test             # vitest (watch)
npm run test:run     # vitest run
npx vitest run --project nuxt                    # component/page tests only
npx vitest run --project e2e                     # needs the Laravel API running + E2E_USER_* (below)
npx vitest run test/nuxt/pages/index.test.ts     # single file
```

The app needs no env vars for local dev (Sanctum `origin`/`baseUrl` are in `nuxt.config.ts`). `.env` (gitignored) holds the e2e settings: `E2E_USER_EMAIL` and `E2E_USER_PASSWORD` (a verified user), plus optional `E2E_API_BASE_URL` (default `http://localhost`) and `E2E_ORIGIN` (default `http://localhost:3000`). They can also be set in the shell, which wins over `.env`. Values are used as typed, `$` included: `test/utils/loadE2eEnv.ts` reads `.env` with Node's `parseEnv`, because Vite's `loadEnv` would expand `$word`. Never print or commit these values.

## Architecture

### Auth and API access: `nuxt-auth-sanctum`

Every API call goes straight from the app (browser or SSR) to the Laravel API through `nuxt-auth-sanctum` in cookie mode (a session cookie plus the `XSRF-TOKEN` CSRF cookie). It is configured in `nuxt.config.ts` (`mode: 'cookie'`, `origin` localhost:3000, `baseUrl` localhost:80, user endpoint `api/v1/user`, `redirectIfUnauthenticated: true`). The old Nitro proxy, which sent one shared bearer token, is gone; don't add Nitro routes that call the Laravel API.

- Reads: `useSanctumFetch` / `useLazySanctumFetch` with `/api/v1/...` (`useLazySanctumFetch('/api/v1/itineraries', { params: { grouped: true } })` in `pages/index.vue`, `useSanctumFetch<TagsResponse>('/api/v1/tags')` in `pages/admin/index.vue`). The user comes from `useSanctumUser()` / `useSanctumAuth()` (`user`, `logout`).
- Mutations: `const client = useSanctumClient()`, then `client<T>(url, { method, body })`. It behaves like `$fetch` (resolves to the parsed body, throws on 4xx/5xx) and adds the base URL, credentials, `Accept: application/json` and the `X-XSRF-TOKEN` header; FormData bodies work as-is. Use `client.raw(...)` only when you need the status or headers (`verify-email.vue`). Never call the API with the global `$fetch`: it goes to the Nuxt origin without the session or the CSRF header.
- Route access: `/admin` uses `definePageMeta({ middleware: ['sanctum:auth'] })`, so guests are sent to `/login`; `login` and `register` use `sanctum:guest`. `/` is public on purpose: guests see the Welcome page, users see their trips. Admin authorization is planned but not built, so any verified user can open `/admin`.
- `redirectIfUnauthenticated: true` means a 401 from a Sanctum-client call in the browser clears the user and sends them to `/login`. A 419 (CSRF token mismatch, e.g. the backend lost its sessions, or the session cookie was deleted but `XSRF-TOKEN` wasn't) neither clears the user nor redirects. Laravel sends no new token with a 419, and the module only fetches one when the cookie is missing, so `app/plugins/sanctum-csrf.client.ts` fetches a new one after every 419, through the module's `sanctum:response` hook (which also runs for `ignoreResponseError` calls). The user's next try then goes through, or gets the 401 a lost session leads to. Never fire an authenticated request for a guest on a public page: gate it, as `pages/index.vue` does with `immediate: !!user.value`. A call made with `ignoreResponseError: true` skips that handling and must deal with a 401 itself (`verify-email.vue` does).

Registration and email verification use the Laravel Fortify routes at the **backend root**, not `/api/v1`: `POST /register`, `/login`, `/logout`, `/email/verification-notification`, all through `useSanctumClient()` (the module adds credentials, `Accept: application/json` and the CSRF header). The current user is `GET /api/v1/user` (`useSanctumUser<User>()`, `User` in `app/types/user.ts`: `first_name`, `last_name`, `email`, `email_verified_at`; there is no `name`). A user with `email_verified_at === null` is unverified: `app/middleware/verification.global.ts` holds them on `/verify-email` (the API answers 403 to places/itineraries/tags). The emailed link is a backend URL, valid for 60 minutes, that redirects back to `/?verified=1` or `/?verified=0`. On a user's first verification it also logs them in when the browser has no session, so `?verified=1` with nobody logged in only happens for an account that was already verified. `app/middleware/verified-flag.global.ts` turns the flag into a toast and removes it from the URL. `POST /email/verification-notification` is limited to one request per 5 minutes per user, shared across all of that user's browsers (the registration email doesn't count). It answers 202 (sent), 204 (already verified), 401 (logged out) or 429 (limit reached). The 429's `Retry-After` is a whole number of seconds, normally 1 to 300 and `0` in the window's last second (meaning try now); CORS exposes it, but not the `X-RateLimit-*` headers. A 204 or a failed send also starts the 5 minutes; a 401 doesn't. `verify-email.vue` mirrors this with the countdown under the button. Domain vocabulary is in `GLOSSARY.md`.

### API shapes

Responses are Laravel resources wrapped in `{ data: ... }`. Types live in `app/types/` (`ItineraryResponse`, `ItinerariesGroupedResponse`, `PlacesResponse`, `TagsResponse`, ...). Dates are `YYYY-MM-DD` strings, or `null` for an unscheduled trip (`Itinerary.start_date/end_date` are `string | null`). Never read them with `new Date("YYYY-MM-DD")`: that is UTC midnight, which is the previous day west of UTC. Use `toLocalDate` / `compareToToday` (`app/utils/date.ts`), or `parseDate` from `@internationalized/date`. Validation errors (422) arrive at `error.data.errors`: the body is `{ message, errors }`, with `errors` shaped `{ field: string[] }`. The user endpoint returns the user object at the top level, not wrapped in `{ data: ... }`.

### Pages, layouts, state

- `pages/index.vue` sets `definePageMeta({ layout: false })` and wraps itself in `<NuxtLayout name="home">`. It is public: when `useSanctumUser()` is empty it renders the Welcome page (`WelcomeHero`, `WelcomeHowItWorks`, and `WelcomeClosing` through `<template v-if="!user" #after>`, the home layout's full-width slot), and it only fetches itineraries for a logged-in user (`immediate: !!user.value`). The Welcome page makes no API request. `useSeoMeta` sets the title for both views and the description, Open Graph and Twitter card tags; `og:image` is `runtimeConfig.public.siteUrl` + `/og-image.png` (set `NUXT_PUBLIC_SITE_URL` in deployment). `public/og-image.png` is a 1200×630 screenshot of `docs/superpowers/specs/2026-11-21-welcome-page-layout-reference.html#seek=15000&nobar`.
- Welcome page hero (`WelcomeRouteScene`): a dashed route draws through three landmarks per city (two on phones, below 768px), loops Tokyo → Paris → Manila → London, and is rendered from `buildScene()` as SVG with CSS animations (`pathLength="1"` + `stroke-dashoffset`; the route is revealed through a mask). `createRouteCycle()` schedules the cities with timers that can be paused; the pause button pauses those and sets `animation-play-state: paused`, and `useHeroPause` remembers it. Reduced motion or a remembered pause shows a still Tokyo (`is-still`). Bubble names are Fraunces 600 at 14px with `font-variation-settings: 'opsz' 14`, which needs the `opsz` axis that `nuxt.config.ts` asks `@nuxt/fonts` for. The drawings and every timing come from `docs/superpowers/specs/2026-11-20-guest-home-hero-reference.html`; keep the two in step.
- Text people read says "trip" in sentence case; code, types, API paths and test ids keep "itinerary" (see `GLOSSARY.md`).
- All state is local `ref`s in the page; no Pinia/store. The exception is the trip page (`pages/trips/[id].vue`): it keeps its days and stops in `useTripDays` and shares them with its components through `provide`/`inject` (`tripDaysKey`, `injectTripDays()`), see `docs/adr/0001-trip-page-state-in-composables.md`. The trip page itself is behind `sanctum:auth`, loads the trip and its stops (three states: not found for a 403 or 404, an error with Try again, and the days' own error), shows every day of the trip with its stops, "Outside the trip dates" for stops on other dates, and "No dates yet" for a trip without dates. Today's date comes only from `useClientToday()` (browser only, so server rendering can't disagree). Edit trip reuses `ItineraryForm` in a modal or sheet; places are added to a day through `TripPlaceSearch`, which stays open until Done. A stop opens in place to show its place (`TripPlaceDetails`), with "Mark as visited" (shown at once, put back if the request fails) and "Edit times" (`TripTimesEditor`, both times always sent together). A stop's or list place's row shows its name (two lines at most) and a photo (76px square below 768px, 144 × 96 from there up); the time sits under the name on a phone and in a column from 768px up; from 768px up the place's details show under the name, cut after two lines, until the row is opened; no city is shown (the place search results show it). The photo is its own button (`TripPlacePhoto`, beside the row's toggle button, never inside it, because a button can't hold a button) that opens the photo viewer (`TripPhotoViewer`: a `UModal` whose default slot is the trigger, holding a `UCarousel`, a strip of small photos and a "n / N" pill; a place with one photo gets no arrows, pill or strip), and a chip with the count sits on the photo when the place has more than one. The viewer's sizes switch with CSS (`md:`), never from script. Stops are reordered by dragging (`useSortable` from `@vueuse/integrations/useSortable` on each day's list; our own `onUpdate` puts the DOM node back and calls `reorderDay`, which re-renders the rows and sends the request; touch needs a 300 ms press and hold, a mouse uses the grip) or with Move up / Move down in the stop's menu. The lists sit beside the days from 1024px and are tabs below it: both panels are always rendered and CSS shows one, so server rendering and hydration agree whatever the window width (never switch the layout from the window width in script). `useTripLists` holds the lists; its create and update responses leave out `items`, `place` and `checklist_items`, so they are merged into local state, never swapped in, and every reorder sends the full list of sibling ids. A new note or checklist takes two requests (the API creates it empty). For a note, a failed second request keeps the created id so a retry sends only the text, and cancelling then deletes the empty note; the kept id is dropped when the lists are loaded again. Notes and checklists are typed right in the list (`TripNoteEditor`, `TripChecklistDraft`, `TripChecklistItem`): Enter adds the next checklist item and is ignored while a save runs. Deleting a list, note or checklist asks first through one confirmation owned by `TripListsColumn` (`confirmDeleteKey`, `injectConfirmDelete()`). Lists, list items and checklist items drag within their own container only (`useDragReorder`), and each has Move up / Move down for people who don't drag. A list place can be added to a day (`TripDayPicker` in `add` mode, no times) and shows "On day N" from `useTripDays().daysWithPlace`. Components deep in the page ask the page to open the day picker ("Move to another day") through `tripDialogs` (`injectTripDialogs()`), another provide/inject. Edit trip warns when new dates would leave stops outside the trip (`ItineraryForm`'s `stopDates` prop; only the trip page passes it). `Grid`/`Form` communicate upward through emits (`isModalOpen`, `isSlideoverOpen`, `isConfirmModalOpen`, `isEditing`, `selectedItinerary`, `itineraryCreated`, `itineraryUpdated`, `loading`), and the page mutates the fetched `itineraries` data locally (insert into the right bucket, splice on delete) rather than refetching. `reorderItineraries()` reassigns the object to force reactivity/ordering.
- Responsive pattern: `useWindowSize` + `isMobile = width < 768`. Desktop uses `ui/Modal`, mobile uses `ui/Slideover` (`side="bottom"`) with the same `ItineraryForm`. Both are inside `<ClientOnly>`. Buttons exist in desktop/mobile variants with different `data-testid`s.
- Forms: `UForm` with `:state` (one `ref({...})` object, not `reactive()`), `@submit`; parent triggers submit through an exposed `triggerSubmit()` (`defineExpose`) that calls `formRef.submit()`. Server validation errors are pushed back with `formRef.setErrors([...])`; any other failure shows an error toast. Create/edit share one form component keyed off `selectedItinerary`. `ItineraryForm` validates with a `validate` function: a name is required, and dates come both or neither ("Clear dates" empties both); creating allows a start from today, editing any start, and an end date is never before the start or today. The date pickers don't report to the form, so it re-checks dates itself while a date error is showing.
- Feedback: `useAppToast().showToast(...)` — success uses `i-lucide-circle-check`; failure uses `'Something went wrong', 'i-lucide-circle-x', 'There was a problem with your request', 'error'`. Tests assert these exact strings.
- Auth pages (`login`, `register`, `verify-email`) use `definePageMeta({ layout: false })` and `<NuxtLayout name="auth">`; `login` and `register` add `middleware: ['sanctum:guest']`. Their feedback is an inline `UAlert` at the top of the card (`role="alert"` for errors), not a toast. Toasts are kept for results shown after a redirect: the `?verified` handler and the session-expired notice. On `verify-email`, a success or info `UAlert` has no role: its text also goes to a status region that is on the page from the start, because screen readers often don't read out a live region that appears with its text already in it. Its Resend button uses `aria-disabled` during the countdown, so it keeps keyboard focus, and gets focus back after the request (loading disables it, and a browser moves focus off a disabled button).
- Loading/error UX: `GridSkeleton` while pending, `EmptyState` with "Try again" (calls `refresh()`) on error, `EmptyState` for no data.
- Past itineraries are read-only: Edit is disabled when `end_date` is before today, and the Past grid isn't wired to edit/delete handlers. A trip without dates is never past. The Trips page's "Unscheduled" group (between Upcoming and Past) holds trips missing a date; the grouped response's `unscheduled` key is optional in the type, so the page works with a backend that doesn't send it.
- Itinerary images are currently a hard-coded `/oc1.jpg` from `public/` via `NuxtImg`.

## Code style

- `<script setup lang="ts">`. Block order is not uniform (`<template>` first in pages, `<script>` first in components) — follow the file you're editing.
- Auto-imports are used for Vue/Nuxt APIs and `app/utils`, `app/composables`; components are also referenced via explicit imports in pages (`@/components/...` or `~/components/...`) — both aliases occur, keep the surrounding file's style.
- Use `import type` for types; shared types go in `app/types/`, not inline in components.
- Keep `components/ui/` wrappers logic-free — they only forward `v-model:open` (via `defineModel`) and expose `button` / `form` / `action` slots, plus a `data-testid` close button (`close-modal-btn`, `close-slideover-btn`, `close-confirm-modal-btn`).
- Stylistic ESLint is enforced: no semicolons, single quotes, 2-space indent, trailing commas, `1tbs` braces with `catch`/`finally` on a new line (`}\n catch {`), consistent quote-props. `no-explicit-any` and `no-multiple-template-root` are off. Run `npm run lint` before finishing.
- Naming: use camelCase for local variables, refs, functions and params, and PascalCase for components (prefer the Nuxt auto-name, e.g. `ItineraryGrid`). Keep snake_case only for API payload/response fields (`start_date`, `end_date`). Older code deviates (`country_names`, `selected_tags`, `new_itinerary`, `old_itinerary`, snake_case params in `utils/date.ts`, `Grid` imported as a bare name in `pages/index.vue`); don't copy those, and don't rename them unless asked.
- Tailwind utility classes inline; theme tokens (`text-primary`, `text-muted`, `text-dimmed`, `bg-neutral-*`) with `dark:` variants. The light-mode primary is teal-700 (`main.css` overrides `--ui-primary`) so white button text passes WCAG AA; don't add `dark:text-white` to primary buttons. Empty fields use `variant="subtle"`, filled use `outline`. Icons are Lucide (`i-lucide-*`).
- Add `data-testid` to any interactive element tests need.

Conventions in `test/nuxt`:
- Mount through helpers in `test/utils/` (`mountIndexPage`, `mountAdminPage`, `mountModal`, `mountSlideover`, `mountLoginPage`, `mountRegisterPage`, `mountVerifyEmailPage`, `mountTripPage`): they `mountSuspended`, register `onTestFinished(() => wrapper.unmount())`, and return `{ wrapper, bodyWrapper }` where `bodyWrapper = new DOMWrapper(document.body)` — needed because Nuxt UI modals/slideovers teleport to `<body>`. `mountIndexPage()` also clicks Create; pass `{ openCreateModal: false }` to skip that (guest view, delete flow), and `attachTo: document.body` when a test looks an element up by id or checks focus (the page mounts detached otherwise).
- Query by `data-testid` / `input[name=...]`; assert open state with `[data-state="open"]`.
- Mock composables with `mockNuxtImport`. Spies come from `vi.hoisted` and are reset in `beforeEach` (`for (const mock of [...]) mock.mockReset()`): `useToast` (`toastAddMock`) and `useSanctumClient` (`clientMock`; assert the URL and options it was called with, and reject it with `{ data: { message, errors }, statusCode: 422 }` for validation errors). Don't stub the global `$fetch`. Data composables (`useLazySanctumFetch`, `useSanctumFetch`, `useFetch`) are mocked as plain functions returning `{ data, pending, error }` refs. `useWindowSize` goes through `vi.mock('@vueuse/core')` using a shared `widthRef` (768 = desktop, 767 = mobile). Fake timers pin "today" (`2026-07-01`) for calendar tests.
- Trip page tests (`test/nuxt/pages/trip.test.ts`) mock `useRoute` (id `t1`) and `useLazySanctumFetch` by URL (the trip, `/spots` and `/lists`), and mount without a `route`: navigating would run `sanctum:auth`, which checks the module's own session state and sends the test to `/login`. The guest redirect is checked on its own in `tripAuth.test.ts`, with nothing mocked.
- A page's route middleware is tested by navigating (`await useRouter().push('/admin')`) and asserting `currentRoute`; files that don't mock `useSanctumUser` run as a guest.
- Group with nested `describe`s (Open/close behavior, Field rendering, Form submission success/error path, ...).
- Global middleware is tested by importing the default export and calling it with a fake `to`, with `navigateTo` and `useSanctumUser` mocked through `mockNuxtImport`. Countdown tests fake only `Date`, `setInterval` and `clearInterval` (`vi.useFakeTimers({ toFake: [...] })`), which is all the countdown uses, so the timers the router and Nuxt UI depend on stay real: with every timer faked, a navigation that waits on a timer never finishes, and a test whose `mountSuspended` has to navigate first hangs. `flushPromises()` works either way (`index.test.ts` fakes every timer).
- `test/nuxt/setup.ts` gives each test its own Vue `idPrefix`. Nuxt UI reports typing to its form 300 ms later, on a channel named after the form's id, and Vue would give the form the same id in every test, so typing at the end of one test could reach the next test's form (`register.test.ts` has a pair of tests for this).
- `RouteScene.test.ts` mocks `usePreferredReducedMotion` (shared `motionRef`) and fakes only `setTimeout`/`clearTimeout`, which is all the city cycle uses. happy-dom runs no CSS animations and has no `getBBox`, so the scene tests check names, classes, labels and timers; how it looks is checked in a browser.
- Tests that open the photo viewer replace `UCarousel` with `test/utils/carouselStub.ts`: `mockComponent('UCarousel', () => import('../../utils/carouselStub'))` at the top of the file. Embla needs layout that happy-dom doesn't have (a zero-size carousel collapses to one snap and can't be navigated), so the stub draws each item next to a button (`carousel-stub-select-N`) that emits `select`, and exposes `emblaApi.scrollTo` as `scrollToMock`. Swiping, the arrow keys and how the viewer looks are checked by eye (`docs/manual-testing/trip-page.md`, section 8).
- Nuxt UI's `UButton` puts its own `data-slot="base"` on its root, overwriting a `data-slot` passed to it (`UHeader`'s menu toggle has none left); find such buttons by `aria-label` ("Open menu"). `UContainer` has no `data-slot` either; the home layout's container has `data-testid="home-container"`.
- Nuxt UI menus open on pointer events and teleport their items to `<body>`, so tests read a menu's items with `menuItems(wrapper, triggerTestId)` (`test/utils/menu.ts`) instead of opening it; give the trigger a `data-testid`. Time-zone tests call `setTimeZone('America/Los_Angeles')` (`test/utils/timeZone.ts`): unsetting `TZ` doesn't reset Node's zone, so the helper puts the original zone back by name, and a test that only unstubs `TZ` leaks Los Angeles time into later tests. Popover calendars from earlier tests can stay in `<body>`, so look a day up inside `[data-testid="end-date-cal"]` (or the start one).
- happy-dom doesn't move focus off an element that becomes disabled, and its `blur()` ignores disabled elements. Where a browser would drop focus (a button that starts loading), move it with `document.body.focus()` (`verify-email.test.ts`, Keyboard focus).

## Git workflow

Feature branches (`feature/...`, `refactor/...`) off `main`, merged via numbered GitHub PRs. Commit subjects are short and lowercase-prefixed (`feature: ...`, `refactor: ...`). `public/oc*.{jpg,webp}` are sample images; `.nuxt`, `.output`, `.env*` are ignored.

## Gotchas

- `serverDir` is `app/server` (non-default) and only holds `api/countries.get.ts`.
- `pages/places.vue` (WIP, untracked) still calls `/api/places`, which no longer exists, and has no `sanctum:auth` guard. The user is migrating it themselves.
- `nuxt.config.ts` hard-codes Sanctum `origin`/`baseUrl` for local dev; they will need env-driven values for any deployment.
- Every nuxt test file starts the Nuxt app in a `beforeAll` hook (`setupNuxt()`), which counts against `hookTimeout`. Page tests load most of the app's modules when the file is imported, before the hook; small files (`useResendCooldown`, the middleware and plugin tests) load them inside it. Run on its own on Windows, such a file took 10–12 s, so Vitest's default 10 s limit skipped it (`Hook timed out in 10000ms`), whether or not Docker was running. In one full run, loading modules was several times slower than usual (transform 168 s, against 35 s when the same command ran again straight after), and the four small files ran past a 30 s limit, so the nuxt project's `hookTimeout` is 60 s.
- While it starts, `nuxt-auth-sanctum` asks the backend at `baseUrl` (localhost:80) for the current user. If the Docker backend accepts connections but never answers, that request runs into the hook timeout and whole files are skipped. Run the suite with `NUXT_PUBLIC_SANCTUM_BASE_URL=http://127.0.0.1:9` so that request fails fast. The log then shows `[nuxt-auth-sanctum:csr] An unexpected error occurred while fetching user identity ... bad port`; that is this lookup failing, not a test failure.
- After changing `fonts` in `nuxt.config.ts`, stop and start the dev server. Its own restart ("nuxt.config.ts updated. Restarting Nuxt...") kept serving the old `@font-face` rules (Fraunces without the `opsz` axis).
- In a scoped `<style>`, don't write `:global(.dark) .x`: Vue replaces a selector that contains `:global()` with its contents, so the rule becomes a bare `.dark { ... }` for the whole app. Write `.dark .x`; scoping only marks the last part.
- `UHeader` has `:toggle="false"`: the header has no menu, and below 1024px the toggle would open an empty one.
- Some existing files have typos/oddities worth leaving alone unless asked (e.g. "occured" in the error empty state, `FormActions.vue` unused, `isDeleted` as a `ref` inside a watcher).
- `README.md` is still the default Nuxt starter and is not a source of truth.
